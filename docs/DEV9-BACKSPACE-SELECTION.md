# v0.5.0-dev.9 — 修复块删除与 Backspace 边界保护的冲突（试验版）

本补丁基于 v0.5.0-dev.8，只调整思源宿主页面的 Backspace 拦截范围。不修改 SimpleMindMap 引擎、iframe 通信、F2、其他快捷键、保存、折叠、标题和导图尺寸。

## 背景与原则

用户报告：思维导图块已选中，右键块菜单显示“删除 Backspace”，但直接按 Backspace 不起作用，必须转移到导图下方段落并重新选块才可以删除。旧代码虽然对 `.protyle-wysiwyg--select` 显式放行，但还会在未识别到明确选择时拦截“导图非编辑外壳”和“编辑器顶层块间隙”，可能与块选择时的 Range 状态冲突。

## 本次修改

- 显式选中块后，Backspace 仍全部交由思源原生处理。
- 无论是否存在 `.protyle-wysiwyg--select` 类名，都不再拦截发生在导图自身外壳、编辑器顶层块间隙的 Backspace。
- 仅在*未选中任何块*、普通文档段落*紧跟导图块后*、光标*确实在该段落开头*时拦截 Backspace。
- 不拦截 Delete、导图 iframe 内事件、文字中间的 Backspace 或其他文档块。

## 风险与已知限制

- 这次**没有**修改焦点管理。如果 Backspace 按键实际上进入了 iframe、菜单或其他焦点元素，而没有到达思源文档的键盘监听，补丁仍可能不足以恢复块删除。
- 当光标处在导图外壳或编辑器顶层间隙，而非普通段落开头时，Backspace 交给思源处理，**该操作有可能删除整张导图**；这与保护范围收紧的取舍一致。
- 仍需在 Windows 思源客户端验证；不要在唯一的重要导图上测试删除。

## 低风险手工验证

1. 在测试文档插入一张可删除的测试导图，确认已保存。
2. 打开块菜单：选择整张导图，关闭菜单后按 Backspace，应按照思源原有方式删除；若没有反应，请记录是否在菜单打开时按键以及是否必须点击文档外区域才生效。
3. 撤销后，将光标放到紧跟导图的普通段落开头，按 Backspace，应保留导图。
4. 在普通段落正文中删除文字，应正常；编辑导图内部文字、删除节点及按 Delete 应保持原行为。
5. 再检查最小化、展开、中心主题标题和保存。
